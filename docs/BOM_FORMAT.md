# Референсний формат BOM-документів

Канон = `docs/docs_first-fixed/Диван Верадо Механізм.md`.
Усі нові / правлені специфікації мають відповідати цьому шаблону.

Formatter (`src/validator/formatter.ts`) підтягує типові артефакти, але **джерело правди — цей формат**.

---

## 1. Рядок матеріалу / напівфабрикату

### Канон

```text
[Emoji?][Назва] (атрибути) - qty uom
```

або без атрибутів / без квадратних дужок (сировина без атрибутів):

```text
Назва - qty uom
```

### Обов’язкові пробіли навколо кількості

| ❌ Погано | ✅ Добре |
|----------|---------|
| `… -1 шт.` | `… - 1 шт.` |
| `… -4 шт.` | `… - 4 шт.` |
| `…)-2шт` | `…) - 2 шт.` |
| `… -1.00шт.` | `… - 1.00 шт.` |

Правило: **пробіл перед `-`, пробіл після `-`, пробіл між числом і UOM**.

Приклади з канону:

```text
[Поролон] (ST-2233 (2000x1600x10)) - 0.704 кг
🪤[Чохол - напівфабрикат] (Д.Верадо Механізм, %Тканина%, %Диван Розмір Бильця%) - 1 шт.
Ножка 115x115 - 4 шт.
Кроватний білий великий з пружинами - 1 шт.
```

## 2. Дужки

### Квадратні `[]`

Товари **з атрибутами** або шаблонні назви (напівфабрикати, нарізки):

```text
🧩[Каркас - нарізані деталі] (100 Дерево Механізм, %Дно Каркасу❌%)
[Поролон] (ST-2233 (2000x1600x10)) - 0.704 кг
```

### Фігурні `{}` (опційно)

Якщо **суфікс після `]`** містить `-` (наприклад `Б-4`, `ПБ-4 м*`), парсер може сприйняти його як кількість / UOM. Огорни **цілий суфікс**:

```text
🪵[Каркас - нарізана деревина] {Б-4}
🪤🧽[Каркас + Поролон - напівфабрикат 2] {Угол Престиж ПБ-4 м*} (%Диван Пружинний Блок%, …)
🧩[Каркас - нарізані деталі] {Б-4} - 1 шт.
```

Імпорт у Odoo **знімає** дужки: ім’я товару = `🪵[Каркас - нарізана деревина] Б-4`. Без `{}` стара поведінка (гіфенений суфікс у кінці рядка → «відсутня одиниця виміру»).

### Круглі `()`

Атрибути / коди / розміри — **завжди в круглих дужках**, одразу після `]`:

```text
[Ніжка] (h30) - 16 шт.
[Ніжка] h30 - 16 шт.          ← ❌ немає дужок
```

### Вкладені дужки (Поролон) — блоки → один формат

Не патчити дужки вручну. Детектити **блоки** і зібрати канон:

| Блок | Приклад |
|------|---------|
| product | `[Поролон]` |
| code | `ST-2233` |
| dims | `2000x1600x10` (латинський `x`) |
| qty + uom | `0.704 кг` |

**Канон MD:**

```text
[Поролон] (ST-2233 (2000x1600x10)) - 0.704 кг
```

**Канон JSON** (`docToJson` → Odoo import):

```json
{
  "templateName": "[Поролон]",
  "attributes": [
    { "attributeName": "Поролон", "value": "ST-2233 (2000x1600x10)" }
  ],
  "qty": 0.704,
  "uom": "кг"
}
```

`value` = `CODE (dims)` — **без** зовнішньої пари дужок (їх дає лише MD-обгортка).

| ❌ Сирий рядок | ✅ Після нормалізації | JSON `value` |
|---------------|----------------------|--------------|
| `[Поролон] ST-2233 (2000x1600x10))) - 0.704 кг` | `[Поролон] (ST-2233 (2000x1600x10)) - 0.704 кг` | `ST-2233 (2000x1600x10)` |
| `[Поролон] (ST-2233 2000x1600x10)). - 0.704 кг` | те саме | те саме |
| `[Поролон] (ST-2233 (2000x1600x10))) - 0.704 кг` | те саме | те саме |
| `Поролон (ST-2233) (2000x1600x10) - 0.704 кг` | те саме | те саме |

Без нормалізації рядок на кшталт `[Поролон] ST-2233 (dims)))` парситься як `value: "2000x1600x10"` (код губиться) — **не імпортувати**.

Formatter: `normalizePorolonLine`. Parser: `rebuildPorolonAttrStr` (defense in depth).

## 3. Крапки — що заборонено

| ❌ | Чому |
|----|------|
| Окремий рядок `.` | Сміття між рядками |
| `…)). - 0.704 кг` | Зайва `.` після дужок |
| `…10). - 0.704` | Крапка замість закриття / артефакт Word |
| `шт` без крапки в кінці рядка кількості | Канон UOM: `шт.` |

Між рядками матеріалів — **порожній рядок або нічого**. Не `.`.

---

## 4. Канонічні UOM

Після форматера дозволені лише:

`шт.` · `кг` · `г` · `m` · `m²` · `m³`

| ❌ | ✅ |
|----|----|
| `кт`, `шт`, `kg`, `м`, `м2` | `шт.`, `кг`, `m`, `m²` |

---

## 5. Emoji-префікси (перед `[`)

| Тип | Emoji |
|-----|-------|
| Нарізана деревина | 🪵 |
| Нарізані деталі / матеріали / компоненти / лист | 🧩 |
| Напівфабрикат | 🪤 |
| Напівфабрикат 2 (каркас + поролон) | 🪤🧽 |

Emoji **перед** `[…]`, ніколи всередині.

---

## 6. Структура цеху (як у Верадо)

```text
# Цех №N … - КОД “Операція (Цех №N)”

<вихідний продукт / BOM-output>
<компоненти з кількістю>

Ціна N грн
```

- Заголовок завжди з `# `.
- Після блоку матеріалів — рядок `Ціна … грн`.
- Варіанти атрибутів у одному цеху розділяє рядок `або` (див. Цех №5 у Верадо).

---

## 7. Швидкий чеклист перед комітом

1. Немає `-N` / `-N.` без пробілу після `-`.
2. Немає рядків, що складаються лише з `.`.
3. Немає зайвих `.` біля `)` перед кількістю.
4. Поролон: `(ST-…. (….x….x….))`.
5. Дужки збалансовані.
6. UOM з канонічного набору.
7. Порівняти зразок рядка з `docs/docs_first-fixed/Диван Верадо Механізм.md`.

## 8. Bad → Good (типові помилки з сирих документів)

```text
❌ Кроватний білий великий з пружинами -1 кт
✅ Кроватний білий великий з пружинами - 1 шт.

❌ Ножка 115x115 -4 шт.
✅ Ножка 115x115 - 4 шт.

❌ .
   (окремий рядок)
✅ (видалити)

❌ 🪤[Чохол - напівфабрикат] (… ) - 1.00 шт.
✅ 🪤[Чохол - напівфабрикат] (…) - 1 шт.
   (пробіли в дужках зайві; qty може бути 1 або 1.00)

❌ [Поролон] (ST-2233 2000x1600x10)). - 0.704 кг
❌ [Поролон] ST-2233 (2000x1600x10))) - 0.704 кг
✅ [Поролон] (ST-2233 (2000x1600x10)) - 0.704 кг
   → JSON: { "attributeName": "Поролон", "value": "ST-2233 (2000x1600x10)" }
```
