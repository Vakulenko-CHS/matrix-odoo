# Нотатки до карток

## T-PRC-01 — extra на тканину (колега 2026-11-05)

Скарга клієнта: одна доплата на всі дивани через «Склад → Налаштування → Атрибути → Типова додаткова ціна». Хотіли свою політику на кожну модель.

Колега: вчора вже писав; **проблеми вже немає**; клієнтам пішла презентація як правильно ставити ціни (на шаблон / PTAV, не глобальний default атрибута).

Агент: картку в `log`. Не міняти базу під цю скаргу, поки клієнт не повернеться з конкретним диваном.

## T-INV-01 — модалка рахунку (перевірено, не баг)

Текст Odoo:

«Недійсна операція. Не вдається створити рахунок-фактура. Немає товарів для виставлення рахунка-фактури.» Далі стандартна порада змінити політику на «Замовлена кількість».

Розбір (cloud, база не змінювалась):

| Замовлення | Рахунок | Стан |
|------------|---------|------|
| S00254 | без номера, Daniil сьогодні 13:39 | чернетка |
| S00256 | РАХ/2026/00056 | підтверджений |
| S00253 | РАХ/2026/00055 | підтверджений |
| S00248 | РАХ/2026/00053 | підтверджений |

У всіх чотирьох повна кількість уже в рахунку. Повторне «Створити рахунок» дає модалку. Чернетка теж рахується як виставлене.

У **87** диванів `invoice_policy` уже «Замовлена кількість». Текст модалки до цього випадку не підходить.

Ймовірно: на S00254 створили рахунок, не підтвердили, знову натиснули «Створити рахунок».

Клієнту: відкрити S00254 → «Рахунки-фактури» вгорі справа → підтвердити чернетку. Новий рахунок не створювати. Товари не чіпати.

## T-SER-01 — зміни 03–04.11 (фрагмент колеги)

- Увімкнено партії/серійники.
- 86 диванів `tracking = serial`. Каркас Короб Реал без tracking.
- Lot 0000001–0000003 на Диван Джаз; 0000001 тестовий.
- Залишки на момент зміни 0, старих quant без номера немає.
- `list_price = 1 ₴` + тестові +100 ₴ на тканини.
- Модалка рахунку = T-INV-01.
