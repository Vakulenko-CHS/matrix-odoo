**Зарплата:** сума з **закритих** WO на ВТК (`state=done`) у періоді листка: `qty_produced × Price Rate` операції; повна сума кожному з `employee_assigned_ids` на WO.

**Не плутати:** модуль **Якість** (`quality.check`) і **операція МО ВТК** (`mrp.workorder` на WC ВТК) — зарплата йде з **WO**, не з кнопки QC (якщо клієнт не скаже інакше).

## Перевірка — зарплата ВТК

### A. Контракт / структура

1. **Працівники** → **Мочалова Тетяна** (і Ліза, Оксана).
2. Вкладка контракту / версії: тип структури **Worker** (не Employee).
3. Дата початку контракту заповнена (**2026-01-01**).

### B. Операції ВТК на МО

1. **Виробництво → Робочі замовлення** (фільтр виконані).
2. Операція з назвою **ВТК …**; поле **Призначено** містить **Мочалова Тетяна** (або іншу з трьох після ручного призначення).
3. **Виробництво → Налаштування → Робочі центри → ВТК** — **Робітник за замовчуванням** = Тетяна.

### C. Розрахунковий лист (головний пруф)

1. **Зарплата → Розрахункові листи → Створити**.
2. Працівник: **Мочалова Тетяна**.
3. Період, де є **done** WO на ВТК (напр. **01.11.2026–30.11.2026**).
4. **Обчислити листок**.
5. У рядках має бути правило **(Цех ВТК) Перевірка якості** / код **п-втк** з сумою > 0, якщо в періоді були її WO на ВТК з `qty_produced` і Price Rate на операції.

Повтор для **Єлизавета** / **Оксана**, якщо їх додавали в **Призначено** на тих самих WO.

### D. CLI (репо)

```bash
npm run qal01-vtk              # dry-run
npm run qal01-vtk -- --apply
```
