# Трекер задач Matrix Odoo

**Джерело правди:** цей каталог, насамперед [`BOARD.md`](./BOARD.md). Агент оновлює дошку в тому ж чаті, де з’явилась нова задача або відповідь.

Slack і **Grok Bot не** є джерелом правди. Grok Bot — окремий агент (логін Cursor ≠ ця дошка). Він не читає `BOARD.md` сам і не синчиться з чатами в Cursor.

Огляд лише локально: `npm run tasks` → [http://localhost:5192/](http://localhost:5192/). Порт у [`dev/ports.json`](../../dev/ports.json). Не Netlify.

## Навіщо не Kanban у Slack зараз

- Slack Lists / canvas / сторонні боти потребують адміна воркспейсу і секрету. Цього в чаті немає.
- Бот у Slack без файлу в git = агент у наступному чаті задачу загубить.
- Дошка в git переживає undo коміту, новий чат і паралельних агентів.

Коли з’явиться токен: дзеркалимо статуси в один канал (короткий рядок `T-FAB-01 next → doing`). Не тримаємо два різних списки.

## Як користуватись

| Колонка в BOARD | Значення |
|-----------------|----------|
| `log` | Розібрано, не робота. Лише знання. |
| `done` | Зроблено в Odoo / репо. |
| `doing` | Зараз у роботі. |
| `next` | Беремо після поточного. |
| Pipeline | У `BOARD` одна колонка на задачу (`doing` / `next` / `backlog` / `low` / `done` / `log`). UI — Kanban усі колонки разом. |
| `вільна` / `чекає` | Не окрема колонка — **тег** на картці (`Доступ` + блокер). |
| `blocked` | Колонка **Блокери** — **тільки зовнішні** паузи (клієнт, колега, немає даних). Не «апрув Іллі». |
| `backlog` | У черзі, пріоритет уже заданий. |
| `low` | Без високого пріоритету (окремий блок колег). |

Правила для агента:

1. Нова задача від колеги → новий рядок з наступним вільним `T-…` id. Не ховати лише в чаті.
2. Зміна статусу → перенос рядка в іншу **pipeline**-секцію (`## Колонка: …`) + `Updated`. Новій задачі — колонка **`Створено`** (ISO дата); якщо немає — UI показує `Updated` як дату появи.
3. Вплив на ліжка → колонка **Beds**. `yes` = не імпортувати ліжка так, ніби цього правила немає.
4. Писати повними реченнями українською. Без жаргону «золото».
5. У картці — **`#### Файли`** і рядок **Канон:** — звичайні markdown-посилання `[назва](шлях#slug-заголовка)`, без backticks у назві. Fragment `#…` = slug заголовка (як у модалці прев’ю). Шлях: `./references/…` або `../../furniture/…`.
6. UI `npm run tasks` — чіпи «Файли», клікабельний **Канон**, модалка з деревом + скрол до якоря (лише dev).
7. Після **відправки тексту клієнту** у Telegram — рядок у [OUTBOUND.md](./OUTBOUND.md) (час локальний, `T-…`, шлях до файлу з текстом), оновити **Блокери** + `Updated` у BOARD і **один рядок** у `#### Лог` (колонка **Джерело:** `Telegram → клієнт`, посилання на `outbound/…`).
8. **`#### Лог`** — хронологія **по суті задачі** (клієнт, колега, Odoo/репо). Окремої секції `#### Повідомлення клієнту` **немає**. Формат — таблиця GFM:

   ```markdown
   #### Лог

   | Коли | Джерело | Подія |
   |------|---------|--------|
   | 2026-11-09 16:46 | Telegram → клієнт | Короткий зміст ([текст](./outbound/…md)) |
   | 2026-11-09 18:34 | Telegram ← Таня | Реакція ❤️; відповіді ще немає |
   | 2026-11-09 | Matrix | Apply в Odoo / Studio (одним реченням) |
   ```

   **Джерело:** `Telegram → клієнт`, `Telegram ← …`, `Колега`, `Matrix`, `Репо`. У **Блокери** — лише поточна пауза (можна «див. лог»).

   **Не вносити в лог:** доручення з чату Cursor про оформлення `BOARD.md`, правила для агента, рефактор UI `apps/tasks`, «додай рядок у лог» — це не історія замовника й не apply по задачі. Extra-правки tasks у Cursor лишаються в git diff / agent-transcript, не в `T-…`.
9. Комітити `apps/tasks/` лише коли Ілля просить коміт.
