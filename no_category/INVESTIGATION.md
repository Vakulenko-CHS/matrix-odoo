## ПРОБЛЕМА 1 — Товари без категорії (19 шт.)

### Причина 1-А: Відсутні ключові слова у `RAW_MATERIAL_CATEGORY`

Файл: `src/tools/importJson/template-bom/importer.ts`

### Причина 1-Б: Напівфабрикати без Цех-категорії

Ці товари **мають власний BOM** (виробляються) і **є компонентами** у вищих BOM — тобто це коректно визначені напівфабрикати. Але функція `applyProductCategories` не змогла знайти Цех-категорію через помилку в назві workcenter'а.

| Товар                                     | Диван            | Проблема                                                |
| ----------------------------------------- | ---------------- | ------------------------------------------------------- |
| `🪤[Каркас - напівфабрикат] Д.Елегант НН` | Диван Елегант НН | Workcenter не має `№N` токена, або 1-я операція порожня |
| `🪤[Каркас - напівфабрикат] Д.Малібу-2`   | Диван Малібу-2   | Те саме                                                 |

**Що перевіряти в doc-файлах:**  
Знайти в `.md` цей товар як заголовок цеху і переконатись що цех написаний у форматі `# Цех №N ...`.

### Причина 1-В: Spelling mismatch — "Тик -так"

| Товар в Odoo | Keyword у коді            | Проблема                        |
| ------------ | ------------------------- | ------------------------------- |
| `Тик -так`   | `'Тік-так'` і `'Tік-так'` | "и" → "і", пробіл перед дефісом |

**Що перевіряти:** у відповідних `.md` файлах знайти рядок `Тик -так` і виправити на `Тік-так`.  
Файли до перевірки: `Диван Лофт Механізм.md`, `Диван Лофт-3 Механізм.md`

## ПРОБЛЕМА 2 — Зайві товари в "Готова продукція / Дивани" (25 шт.)

### Коренева причина: Невідповідність назви між "виробляється" і "використовується як компонент"

Це **головна причина всіх 25 помилок**. Парсер будує `templateName` з атрибутного скорочення у дужках `(...)`. Якщо в doc-файлі одні і ті самі дужки написані по-різному — утворюються **два різні шаблони в Odoo**.

#### Конкретний приклад — `Диван Лофт-3 Механізм.md`

```
Цех №5 (виробляється):
  🧩[Поролон - нарізані компоненти] (Д.Лофт-3, %Диван Пружинний Блок%, ...)
  → templateName = "🧩[Поролон - нарізані компоненти] Д.Лофт-3"

Цех №6 (використовується як компонент):
  🧩[Поролон - нарізані компоненти] (Д.Лофт-3 Механізм) - 1 шт.
  → templateName = "🧩[Поролон - нарізані компоненти] Д.Лофт-3 Механізм"
```

**Різниця: `Д.Лофт-3` vs `Д.Лофт-3 Механізм`**  
Парсер створює два окремих записи. Перший (`Д.Лофт-3`) — в `manufacturedNames` але **не** в `componentNames` → алгоритм думає що це фінальний продукт → `finalCatId`. Другий (`Д.Лофт-3 Механізм`) — тільки в `componentNames` → без категорії або неправильна.

#### Аналогічний баг — `Диван Доррі Механізм.md`

```
Цех №5: 🧩[Поролон - нарізані компоненти] (Д.Доррі, ...)
         → "🧩[Поролон - нарізані компоненти] Д.Доррі"

Цех №6: 🧩[Поролон - нарізані компоненти] (Д.Доррі Механізм) - 1 шт.
         → "🧩[Поролон - нарізані компоненти] Д.Доррі Механізм"
```

## Схема перевірки doc-файлу (чекліст)

При перегляді кожного `.md` файлу перевіряти наступне:

### ✅ Правило 1 — Консистентність скорочення `(...)`

Для кожного напівфабрикату (`🧩`, `🪤`, `🪤🧽`, `🪵`) знайти:

1. Рядок де він є **заголовком** (перший рядок без `- N шт.`)
2. Всі рядки де він є **компонентом** (закінчуються на `- N шт.`)

Перший аргумент у `(...)` (модель-скорочення) **повинен збігатися** у всіх цих рядках.

```
❌ БАГ:
  🧩[Поролон - нарізані компоненти] (Д.Лофт-3, ...)       ← "Д.Лофт-3"
  🧩[Поролон - нарізані компоненти] (Д.Лофт-3 Механізм)   ← "Д.Лофт-3 Механізм"

✅ ВИПРАВЛЕНО:
  🧩[Поролон - нарізані компоненти] (Д.Лофт-3 Механізм, ...)
  🧩[Поролон - нарізані компоненти] (Д.Лофт-3 Механізм)
```

### ✅ Правило 2 — Написання `Тік-так`

Перевірити рядок з Тік-так: `Тік-так - N шт.` (з "і", без пробілу перед `-`).

### ✅ Правило 3 — Послуга Перевірка Якості

Рядок у розділі `# ВТК` повинен бути: `(Послуга) Перевірка Якості - 1 шт.`  
НЕ: `Перевірка Якості - 1 шт.`

### ✅ Правило 4 — Товари сировини без ключових слів

Якщо є товари `[Подушка]`, `[Наволочка]`, `Блюз`, `Додатковий пруж.блюз `, `Крюк`, `Кріплення ламелі`, `Опора средняя` — вони ПОВИННІ фігурувати або:

- а) Тільки як компоненти (`- N шт.`) — тоді треба додати ключові слова до `RAW_MATERIAL_CATEGORY` в importer.ts
- б) Як заголовок цеху і компонент у вищому цеху — тоді назви мають збігатися (Правило 1)

## Наступні кроки

1. **Виправити doc-файли** по переліку вище (Правила 1–4)
2. **Після фіксу** — `npm run export-json docs/docs_first-fixed/<файл>.md` і перевірити JSON
3. **Запустити тулзу валідації** (буде створена) щоб виловлювати ці помилки до імпорту
4. **Видалити проблемні дивани** командою: `npm run restore -- "Диван Назва Моделі"`
5. **Перевторно імпортувати** вже виправлені файли: `npm run import-template-bom exports/...`

### Дивани до видалення і повторного імпорту (пріоритет)

Ті що мають підтверджений баг "різна назва":

- `Диван Лофт-3 Механізм` + `Диван Лофт-3 Колеса`
- `Диван Доррі Механізм` + `Диван Доррі Колеса` + `Диван Доррі-3 *`
- `Диван Нео *` (Нео, Нео-3, Нео 196) — всі варіанти
- `Диван Леон-Люкс *`
- `Диван Хіт *`
- `Диван Лілі *` ← з `_bad/fixed/`
- `Диван Угол Лофт-2 *`
- `Диван Угол Лофт-3 *`
- `Диван Угол Реал-Т` ← з `_bad/fixed/`
- `Диван Елегант НН`
